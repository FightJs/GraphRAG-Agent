## 一、产品概述

### 1.1 产品定位

**GraphRAG Agent** 是面向知识密集型文档的多模态智能问答平台。用户上传多种格式文档，系统自动完成结构化解析、知识图谱（KG）构建，并提供基于图谱与向量检索的混合式智能问答服务。

**v2.0 定位升级：** 从「单文档 KG 问答工具」进化为「企业级多模态知识库管理平台」，支持多文档跨库联合问答、混合检索（KG + Vector）、流式输出、KG 人工编辑与知识库团队管理。

### 1.2 核心目标

| # | 目标 | v1.0 | v2.0 |
|---|---|---|---|
| G1 | 多格式文档一键索引 | ✅ 单文档 | ✅ 批量导入、文件夹组织 |
| G2 | 准确可追溯的问答 | ✅ KG-Only | ✅ KG + Vector 混合，来源段落展示 |
| G3 | KG 可视化探索 | ✅ 只读查看 | ✅ 支持人工编辑节点/边 |
| G4 | 知识库持久管理 | ✅ 单用户文档列表 | ✅ 用户账户 + 知识库 + 团队共享 |
| G5 | 实时流式响应 | ❌ | ✅ 打字机效果输出，首字延迟 ≤ 2s |
| G6 | 多文档联合问答 | ❌ | ✅ 跨文档语义检索+合并回答 |

### 1.3 产品边界（v2.0）

**新增功能（v2.0 全量）：**
- 用户账户体系与 JWT 认证
- 文档分组（知识库/文件夹）管理
- 问答答案评分（👍/👎）与反馈收集
- Webhook 回调通知（索引完成事件）
- 向量检索 + KG 混合模式（支持大型文档 KG > 200 节点）
- 多文档跨库联合问答
- 流式输出（Streaming）响应
- KG 人工编辑（节点/边增删改）

**仍不包含（v3.0 规划）：**
- 多语言界面（英语/日语）
- 文档公开分享（链接分享）
- API 开放平台（第三方集成）

## 二、目标用户与使用场景

### 2.1 用户画像

#### Persona A — HR 招聘专员（核心用户，继承 v1.0）
- **背景：** 每日处理数十份候选人简历，需快速定位候选人核心技能和工作经历
- **v2.0 新增需求：** 多份简历进入同一知识库，横向批量对比（"哪几位候选人掌握 LangChain？"）
- **新核心诉求：** 跨文档联合问答 + 知识库分组管理

#### Persona B — 研究人员 / 知识工作者（继承 v1.0）
- **背景：** 管理大量研究报告（单份可能超200页）、行业白皮书
- **v2.0 新增需求：** 大文档 KG 节点超 200 时需向量辅助检索；问答时需显示答案来源原文段落
- **新核心诉求：** 混合检索 + 来源段落溯源

#### Persona C — 企业合规 / 法务审查员（继承 v1.0）
- **背景：** 审查合同、政策文档，提取关键条款
- **v2.0 新增需求：** 批量导入多份合同，KG 人工校正 OCR 错误节点
- **新核心诉求：** KG 编辑修正 + 批量文档管理

#### Persona D — 企业知识库管理员（v2.0 新增）
- **背景：** 负责维护公司内部知识库，需管理多人、多部门的文档资产
- **痛点：** 文档散乱，无组织结构，无法追踪各文档索引状态
- **使用场景：** 创建知识库 → 批量导入文档 → 监控索引状态 → 管理团队成员
- **核心诉求：** 用户账户体系、知识库组织管理、系统使用统计

### 2.2 核心使用场景（v2.0 扩展）

| 场景 | 描述 | 关键功能 | 新增版本 |
|---|---|---|---|
| 简历快速筛查 | 单份简历 KG 问答 | 文档上传、单文档问答 | v1.0 |
| 知识文档探索 | KG 图谱节点/关系浏览 | KG 可视化 | v1.0 |
| 多简历横向对比 | 多份简历进同一知识库，跨文档对比 | 知识库、多文档问答 | v2.0 |
| 大文档深度检索 | 超200页报告混合检索，答案标注来源段落 | 混合模式、来源追踪 | v2.0 |
| 实时流式问答 | 答案逐字出现，首字 ≤ 2s 延迟 | Streaming 响应 | v2.0 |
| KG 人工校正 | 修复 OCR 识别错误节点（如"并冈山大学"→"井冈山大学"） | KG 编辑器 | v2.0 |
| 团队知识库管理 | 管理员维护部门知识库，统计使用情况 | 账户体系、知识库管理 | v2.0 |

## 三、核心业务痛点

| 痛点 | 传统方案局限 | v1.0 解法 | v2.0 升级 |
|---|---|---|---|
| **文档格式多样** | 手动工具切换 | 统一上传，自动路由 MinerU | 批量导入，文件夹组织 |
| **知识碎片化** | 关键词搜索粒度粗 | KG 三元组结构化问答 | KG + Vector 混合，双重检索 |
| **大文档检索失效** | KG-Only 在 >200 节点时 Token 溢出 | 不支持 | 自动切换混合模式，向量检索辅助 |
| **多文档无法关联** | 各文档独立孤立 | 不支持 | 知识库聚合，跨文档联合问答 |
| **答案不可追溯** | LLM 直接回答，无来源 | KG 节点边可查验 | 额外展示原文段落引用（Vector 来源） |
| **OCR 错误无法修正** | 错误固化在 KG 中 | 只读，不可修改 | KG 编辑器支持人工修正节点/边 |
| **索引等待无反馈** | 空白等待 | 5 阶段进度条 | 同 v1.0 + Webhook 回调推送 |
| **响应等待感强** | 完整答案等待 5–8 秒 | 不支持 | Streaming 流式输出，首字 ≤ 2s |
| **无账户隔离** | 所有文档共享，无权限 | 无账户 | JWT 认证 + 知识库访问权限 |

## 五、完整产品流程

### 5.1 主流程总览（v2.0）

```
[入口] 登录 → 选择知识库（或新建）
    │
    ▼
[Step 1] 上传文档（单个 / 批量）
    文件选择 → 参数配置 → 提交 → 获得 doc_id，状态="已上传"
    │
    ▼
[Step 2] 启动索引（单个 / 批量启动）
    获得 task_id，异步进入5阶段 Pipeline
    │
    ▼
[Step 3] 索引进度等待（轮询 / Webhook 通知）
    完成 → 状态="已索引" → 可选：KG 人工编辑修正
    │
    ▼
[Step 4] 选择检索模式
    ├─ KG-Only（默认，适合 KG ≤ 200 节点）
    └─ 混合模式（自动推荐，KG > 200 节点时触发）
    │
    ▼
[Step 5] 智能问答
    ├─ 单文档问答（流式输出）
    └─ 多文档知识库联合问答
    │
    ▼
[Step 6] 结果反馈 + 历史管理
    答案评分（👍/👎）→ 历史保存 → 可复查复制
```

### 5.2 用户账户流程（v2.0 新增）

```
[首次访问]
    │
    ├─ 注册页：输入邮箱 + 密码 + 昵称
    │   → POST /api/v2/auth/register
    │   → 邮件验证（点击验证链接激活账户）
    │
    └─ 登录页：邮箱+密码 or Google OAuth
        → POST /api/v2/auth/login
        → 获得 JWT Access Token（24h）+ Refresh Token（7d）
        → Token 存入 httpOnly Cookie
        │
        ▼
    [主界面] 知识库列表页
        ├─ 首次登录：引导创建第一个知识库
        └─ 已有知识库：直接展示知识库 Grid

[Token 过期处理]
    → 自动静默刷新（Refresh Token 未过期）
    → Refresh Token 过期 → 跳转登录页 + Toast "登录已过期"
```

### 5.3 知识库管理流程（v2.0 新增）

```
[知识库列表页]
    │
    ├─ 点击"新建知识库"
    │   → 输入名称 + 描述 + 选择图标颜色
    │   → POST /api/v2/kbs → 创建成功，进入知识库首页
    │
    ├─ 点击已有知识库
    │   → 进入知识库首页（等同于 v1.0 的文档库首页，但作用域限于当前知识库）
    │
    └─ 批量导入文档至知识库
        → 选择多个文件（zip 压缩包 or 多文件）
        → 上传成功后批量启动索引
        → 知识库统计更新（文档数 / 节点数）
```

### 5.4 混合检索模式流程（v2.0 新增）

```
[Q&A 页面] 用户输入问题
    │
    ├─ 系统判断当前文档 KG 规模
    │   ├─ KG 节点数 ≤ 200：默认 KG-Only 模式（全量 KG 注入 SystemMessage）
    │   └─ KG 节点数 > 200：推荐混合模式（弹出 Banner 提示用户切换）
    │
    ├─ KG-Only 模式
    │   └─ 全量 KG 序列化 → SystemMessage → DeepSeek → 流式输出答案
    │
    └─ 混合模式
        ├─ [并行执行]
        │   ├─ KG 检索：问题 → 实体关系匹配 → 相关 KG 子图
        │   └─ Vector 检索：问题 → Embedding → Top-K 语义段落
        │
        ├─ 结果合并：KG 子图 + Top-K 段落 → 合并上下文
        ├─ DeepSeek 生成答案（流式输出）
        └─ 答案中追加"来源段落"折叠区（可展开查看原文定位）
```

### 5.5 多文档联合问答流程（v2.0 新增）

```
[Q&A 页面] 切换为"知识库问答"Tab
    │
    ├─ 范围选择：
    │   ├─ 当前知识库（全部已索引文档）
    │   └─ 手动勾选（最多 10 个文档）
    │
    ├─ 输入问题 → 发送
    │   ├─ Vector 检索在选定文档中召回 Top-K 段落（跨文档）
    │   ├─ 各文档 KG 子图检索（关键实体匹配）
    │   └─ 合并上下文 → DeepSeek → 流式输出
    │
    └─ 答案展示
        ├─ 答案文本（流式打字机效果）
        └─ 来源追踪：每条引用标注 [文档名 · 页码]，点击跳转文档详情
```

### 5.6 KG 人工编辑流程（v2.0 新增）

```
[KG 页面] → 点击右上角"编辑模式"按钮
    │
    ├─ 进入编辑模式（画布边框变橙色，提示"编辑模式"）
    │
    ├─ 编辑节点
    │   ├─ 双击节点 → 弹出编辑 Panel
    │   │   ├─ 修改 label（如 "并冈山大学" → "井冈山大学"）
    │   │   ├─ 修改 type（实体类型）
    │   │   └─ 修改 attributes（JSON 编辑器）
    │   └─ 右键节点 → 菜单：删除节点（级联删除相关边）
    │
    ├─ 新增节点
    │   └─ 画布空白处右键 → "新增节点" → 填写 label/type/attributes
    │
    ├─ 编辑边
    │   └─ 点击边 → 编辑 relation 文字 / 修改 source/target
    │
    ├─ 新增边
    │   └─ 拖拽节点 A 到节点 B → 弹出"关系类型"输入框 → 确认创建
    │
    └─ 保存 / 放弃
        ├─ 点击"保存更改" → PATCH /api/v2/kg/{doc_id} → 成功后退出编辑模式
        └─ 点击"放弃更改" → 二次确认 → 恢复编辑前状态

```

### 5.7 流式问答交互流程（v2.0 新增）

```
[发送问题]
    │
    ├─ POST /api/v1/qa/query（带 stream=true 参数）
    │   └─ 服务端：Server-Sent Events（SSE）流式推送
    │
    ├─ 前端接收 SSE
    │   ├─ event: "delta"  → 每次追加 delta.content 到答案气泡
    │   ├─ event: "done"   → 停止追加，显示完整元信息（token/finish_reason）
    │   └─ event: "error"  → 显示错误气泡，提供重试按钮
    │
    └─ 交互状态
        ├─ 流式进行中：显示光标闪烁效果（▌）
        ├─ 发送按钮变为"停止"按钮（点击可中断流式）
        └─ 流式完成：光标消失，元信息栏更新，评分按钮出现
```

## 七、核心交互逻辑

### 7.1 文档状态机与按钮可用性（继承 v1.0，新增批量操作）

```
上传成功 ──▶ [uploaded] ──启动索引──▶ [indexing] ──完成──▶ [indexed]
                │                          │                    │
                │                          │失败                │删除KG
                │                          ▼                    ▼
                │                       [failed]          [uploaded]
                │                          │
                └──────────────────────────┘（重新索引）
```

**按钮可用性矩阵（v2.0 新增批量启动/编辑KG）：**

| 操作 | uploaded | indexing | indexed | failed |
|---|---|---|---|---|
| 开始索引 | ✅ | ⛔灰色 | ✅重新索引 | ✅重试 |
| 查看图谱 | ⛔ | ⛔ | ✅ | ⛔ |
| **编辑 KG** | ⛔ | ⛔ | ✅ | ⛔ |
| 开始问答 | ⛔ | ⛔ | ✅ | ⛔ |
| 批量选中启动索引 | ✅多文档选中 | — | ✅重新索引 | ✅重试 |
| 删除文档 | ✅二次确认 | ⚠️ | ✅二次确认 | ✅ |

### 7.2 流式问答状态机（v2.0）

```
[空闲] 用户输入 → 按钮可用
    │ Ctrl+Enter / 点击发送
    ▼
[请求中] 发送 POST + stream=true
    ├─ 发送按钮 → "停止 ■" 按钮（可中断）
    └─ 答案气泡出现，内容为空 + 光标 ▌
    │
    ▼ SSE event: delta (循环接收)
[流式中] delta.content 追加至气泡
    ├─ 打字机动画（content 逐段追加）
    └─ 用户点击"停止"→ 关闭 SSE 连接 → 进入[完成]
    │
    ▼ SSE event: done
[完成]
    ├─ 光标消失
    ├─ 元信息栏更新（token 消耗 / finish_reason）
    ├─ finish_reason="length" → 答案末尾显示黄色截断提示
    └─ 显示 👍/👎 评分按钮（C-17 FeedbackRating）
    │
[评分] 用户点击 👍 或 👎
    ├─ POST /api/v2/qa/{query_id}/feedback
    ├─ 收到反馈后可选弹出"补充说明"文本框（最多 200 字）
    └─ 提交后评分按钮变为已选中态，不可重复提交
```

### 7.3 检索模式自动推荐逻辑（v2.0）

```
用户打开问答页
    │
    ├─ 系统读取 kg["meta"]["total_nodes"]
    │   ├─ ≤ 200 节点 → 默认 KG-Only，RetrievalModeSwitch 显示"KG-Only（已选）"
    │   └─ > 200 节点 → 默认混合模式，顶部黄色 Banner：
    │       "该文档 KG 较大（XXX 节点），已自动切换为混合检索模式以获得更好效果"
    │       Banner 包含"了解更多"链接 + "不再提示" 选项
    │
    └─ 用户可随时手动切换（Toggle Switch）
        切换时 Toast 提示："已切换为 [模式名] 模式，下次问答生效"
```

### 7.4 KG 编辑器交互逻辑（v2.0）

**进入/退出编辑模式：**
- 点击"编辑模式"按钮 → 顶部出现橙色状态条 + 画布节点变为可拖拽可选中样式
- 有未保存修改时，点击页面离开（路由跳转/关闭标签）→ 弹出"有未保存的修改，确认离开？"

**撤销/重做栈：**
- 支持 Ctrl+Z / Ctrl+Y（最多50步撤销）
- 每次操作（增/删/改节点或边）推入操作栈
- 未保存前操作栈仅在内存中，刷新清空

**保存机制：**
- 点击"保存更改" → `PATCH /api/v2/kg/{doc_id}` → 
  - 成功：橙色状态条消失 + Toast"KG 已更新（修改了 3 处）" → 退出编辑模式
  - 失败：Toast 错误提示，保留编辑状态，可重试

### 7.5 多文档选择逻辑（v2.0）

```
知识库问答页 左侧面板：
    ├─ 全选开关 → 选中知识库内全部已索引文档
    ├─ 单个 CheckBox → 选中/取消
    ├─ 已选文档数量实时显示："已选 X / Y 份"
    └─ 上限：最多同时选 10 份文档
        超过 10 份时：新勾选触发 Toast "最多同时选 10 份文档参与检索"
        并自动取消该次勾选

未索引文档（status != indexed）：
    └─ CheckBox 灰显 + Tooltip："该文档尚未完成索引"
```

### 7.6 Webhook 配置与通知逻辑（v1.1）

**配置入口：** 启动索引 Modal 底部 + 设置页 Webhook 管理

**Webhook 事件类型：**

| 事件 | 触发时机 | payload 关键字段 |
|---|---|---|
| `index.completed` | 索引成功完成 | doc_id, task_id, kg_nodes, kg_edges |
| `index.failed` | 索引失败 | doc_id, task_id, error_code, error_msg |

**Webhook 调用规则：**
- HTTP POST，JSON body，包含 `event`、`timestamp`、`data` 三个顶层字段
- 失败重试：最多重试3次（间隔 1min / 5min / 15min）
- Webhook 日志保留 7 天，可在 P-12 查看调用历史

### 7.7 账户认证状态管理（v1.1）

| 状态 | 触发场景 | 前端行为 |
|---|---|---|
| 未登录 | 直接访问任意需认证页面 | 重定向至 `/login?redirect=当前URL` |
| Token 即将过期（剩余 < 5 分钟） | 每次 API 响应后检查 | 静默调用 Refresh Token 接口更新 |
| Access Token 过期 | 任意 API 返回 401 | 自动 Refresh → 重试原请求 |
| Refresh Token 过期 | Refresh 接口返回 401 | 清除本地 Token → 跳转登录页 + Toast |

| 场景 | 处理方式 |

| 网络断开（流式中） | 检测到 offline 事件 → 中止流式 → 顶部 Banner + 气泡提示 |
| Refresh Token 过期 | 跳转登录页 + 保存当前路由 URL → 登录后自动跳回 |

### 9.3 安全性要求（v2.0 升级）

| 要求 | 说明 |
|---|---|
| JWT 认证 | Access Token（24h）+ Refresh Token（7d）；存储于 httpOnly Cookie |
| CSRF 防护 | SameSite=Strict Cookie + 双提交 Cookie 模式 |
| 文件上传校验 | MIME type + 扩展名双重校验；服务端限制文件大小 |
| 删除操作确认 | 需手动输入文档名确认，防误操作 |

| KG 编辑权限 | 仅文档所有者（创建人）可进入编辑模式（v3.0 团队权限细化） |
| Webhook 签名 | Webhook payload 附带 HMAC-SHA256 签名，接收方可验证来源 |
| 日志脱敏 | 问题/答案内容不写入服务端访问日志 |
